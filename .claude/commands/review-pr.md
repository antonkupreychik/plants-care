Запусти ревью на PR #$1.

## Шаги

1. `gh pr view $1` — получи метаданные PR (заголовок, описание, ветка-источник, **ветка-цель/base**, связанные issue).
2. Проверь `git status` — дерево должно быть чистым. Если есть незакоммиченные изменения — **СТОП**, не делай checkout поверх них. Затем `gh pr checkout $1` (лучше в отдельный worktree, чтобы не трогать текущую ветку).
3. Делегируй **reviewer**:
    - Передай: какой PR (#$1), какой issue он закрывает (если указан в описании через `Closes #N`), какая branch, **какая base-ветка PR** (из шага 1).
    - Reviewer смотрит дифф PR через `gh pr diff $1` (база PR может быть `develop` или `main` — не хардкоди `main`) и прогоняет `./mvnw verify`.
4. Получи от reviewer отчёт в стандартном формате (🔴 BLOCKING / 🟡 SHOULD FIX / 🟢 NIT / Verdict).
5. Покажи отчёт мне в чате **без изменений** (не сокращай, не интерпретируй).
6. Спроси, что делать дальше:
    - Запостить ревью комментарием в PR (`gh pr review $1 --comment --body-file <report>`)?
    - Запросить изменения (`gh pr review $1 --request-changes --body-file <report>`)?
    - Апрувнуть (`gh pr review $1 --approve`) — только если LGTM без BLOCKING?
    - Просто оставить себе и ничего не делать в GitHub?

## Чего ты не делаешь

- Не правишь код в PR. Это работа автора PR.
- Не апрувишь автоматически — ВСЕГДА жди моей команды.
- Не комментируешь в issue, только в PR.
- Не закрываешь PR.

Если reviewer находит критичные баги — обозначь их явно в начале своего сообщения мне, чтобы я не пропустил.
