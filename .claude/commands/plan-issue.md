Подготовь issue #$1 к работе агентов. Реализовывать сегодня **не надо**, только спланировать.

## Шаги

1. `gh issue view $1` — прочитай задачу полностью, включая комментарии и связанные issue.

2. Проверь, есть ли в issue **acceptance criteria** в явном виде (чек-лист, «должно работать так-то»). Оцени:
    - Понятно ли, что считается «готово»?
    - Понятно ли, какие edge cases учитывать?
    - Есть ли упоминание таймзон / шедулера / БД — нужно ли быть особенно аккуратным?

3. Прочитай связанный код. Используй `Glob`/`Grep` чтобы найти, где сейчас живёт похожая функциональность. Если фича расширяет существующее — изучи паттерн.

4. Составь **план реализации** в формате:

   ```
   ## План для #$1: <название>

   ### Acceptance criteria (как поняли)
   - [ ] <уточнённый AC 1>
   - [ ] <уточнённый AC 2>
   - ...

   ### Затрагиваемые модули
   - <пакет/файл>: <что меняется>
   - ...

   ### План работ
   1. **Миграция БД** (если нужна): <что>, backward-compat риски
   2. **Domain/Repository**: <что меняем>
   3. **Service**: <что меняем>
   4. **Telegram handler / Controller**: <что меняем>
   5. **Тесты**: <минимальный набор сценариев>
   6. **Документация**: <README обновляем? новые env? javadoc?>

   ### Риски и открытые вопросы
   - <риск 1>
   - <вопрос, на который нужен ответ перед стартом>

   ### Оценка категории (автономность)
   - [ ] Полностью автономно (`/ship-issue $1`)
   - [ ] Supervised (план утверждён, дальше /ship-issue)
   - [ ] Pair-programming (делаем вместе, без автомата)
   - [ ] Не отдавать агенту (делает человек)
   ```

5. **Покажи план мне в чате.** НЕ постируй его в issue автоматически.

6. Если я говорю «ок, запиши» — `gh issue comment $1 --body-file <plan>`.
   Если я прошу уточнения — переделай и покажи снова.

## Что делаешь, если задача мутная

Не пытайся «допридумать» AC. Лучше выдай план с явной секцией «не хватает информации» и списком конкретных вопросов:
- Какое поведение при отсутствии пользователя?
- Какой лимит на размер списка?
- Уведомлять ли пользователя при ошибке отправки?

Я отвечу, и тогда переделаешь план.

## Чего не делаешь на этом шаге

- Не создаёшь ветку.
- Не пишешь код.
- Не делегируешь spring-coder.
- Не редактируешь файлы в репо.

Только чтение + план.
