# Флоу: продуктовый слой → исполнение

Два слоя агентов. Верхний (новый) превращает твоё мышление в Notion в задачи.
Нижний (собрали раньше) превращает задачи в код.

```
┌────────────────────────────────────────────────────────────────┐
│  ТВОЁ МЫШЛЕНИЕ — Notion                                          │
│  Roadmap · ADR · Ideas/Parking lot · Mobile Roadmap             │
└───────────────────────────┬────────────────────────────────────┘
                            │ агенты читают как контекст (Notion MCP)
                            ▼
┌────────────────────────────────────────────────────────────────┐
│  ПРОДУКТОВЫЙ СЛОЙ (новый)                                        │
│                                                                  │
│  /sync-check       → backlog-analyst                            │
│     сверяет Notion ↔ GitHub, ловит дрейф, предлагает что зреет  │
│                                                                  │
│  /design-feature X → adr-designer                               │
│     проектирует решение, пишет ADR (Proposed) в твоём шаблоне   │
│                                                                  │
│  /promote-idea X   → task-generator                             │
│     идея/❌ → готовый GitHub issue с AC, проверка по ADR         │
└───────────────────────────┬────────────────────────────────────┘
                            │ создаёт issues (после твоего ✅)
                            ▼
                  ╔═══════════════════╗
                  ║   ЧЕЛОВЕЧЕСКИЙ     ║   ты подтверждаешь:
                  ║   ГЕЙТ            ║   issue завести / ADR принять /
                  ╚═════════╤═════════╝   статус обновить
                            ▼
┌────────────────────────────────────────────────────────────────┐
│  ИСПОЛНИТЕЛЬНЫЙ СЛОЙ (собрали раньше)                            │
│                                                                  │
│  /plan-issue N  → разбор issue, уточнение AC                    │
│  /ship-issue N  → spring-coder → flyway-migrator → test-writer  │
│                   → reviewer → docs-writer → PR                 │
│  /review-pr N   → reviewer на существующий PR                   │
└───────────────────────────┬────────────────────────────────────┘
                            │ PR
                            ▼
                  ╔═══════════════════╗
                  ║  ТЫ МЕРЖИШЬ PR    ║
                  ╚═════════╤═════════╝
                            │ после мержа
                            ▼
        /sync-check → backlog-analyst обновляет статус
        в Notion Roadmap (🟠 → ✅) — петля замыкается,
        дрейф не копится
```

## Типичные циклы

### Цикл «новая фича из головы»
```
идея → /design-feature "Дни рождения растений"
     → обсудили ADR, принял
     → /promote-idea "Дни рождения растений"
     → проверил issue(s), завёл
     → /ship-issue <N>
     → посмотрел PR, смержил
     → /sync-check (обновить Notion)
```

### Цикл «разгрести бэклог»
```
/sync-check
  → дрейф статусов поправили в Notion
  → увидел список 💭/❌ кандидатов
  → /promote-idea по тем, что дозрели
  → дальше /ship-issue по новым issues
```

### Цикл «закрыть открытый вопрос мобилки»
```
/design-feature "Хранилище фото R2 vs Yandex"
  → adr-designer дал ADR с вариантами и рекомендацией
  → принял решение, ADR → Accepted
  → /promote-idea "Вынос фото в S3" → issues на Mobile Phase 0
```

## Принцип разделения

- **Продуктовые агенты НЕ пишут код.** Их выход — issues и ADR.
- **Исполнительные агенты НЕ принимают продуктовых решений.** Их вход — готовый issue с AC.
- **Человеческий гейт между слоями обязателен.** Агенты готовят, ты решаешь. Это совпадает с твоим принципом из Parking lot: «проверять раз в месяц».

## Что нужно подключить

1. **Notion MCP** — уже подключён (агенты читают твои страницы).
2. **GitHub MCP** или `gh` CLI — для issues/PR.
3. ID страниц Notion зашиты в промпты агентов. Если переедешь/пересоздашь страницы — обнови ID в `task-generator.md`, `adr-designer.md`, `backlog-analyst.md`.

## С чего начать

1. `/sync-check` — первым делом. Увидишь реальное состояние бэклога и дрейф (там точно есть рассинхрон статусов Этапа 2).
2. Поправь статусы в Notion по отчёту.
3. Возьми один пункт из «Топ-3 кандидата» Parking lot (например Snooze) → `/promote-idea` → `/ship-issue`. Прогонишь полный цикл сверху донизу на одной задаче.
4. Дальше масштабируй.
